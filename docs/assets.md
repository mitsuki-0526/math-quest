- 作成日: 2026-09-24
- ステータス: 画風決定(2026-09-24: **A. ドット絵風**)。基準画像 = マイナススライム
- 関連: 要件 F90〜F92・§9 Q2 / [設定資料](setting.md)(人物・敵の姿) / [台本](script/g1/)(敵の「元の姿」) / `src/assets/manifest.ts`(素材ID)

## 1. 方針

- **ゲームは素材なしで全部動く**(F90)。素材は「あとから差し替えるもの」で、1枚ずつ足してよい。途中で止めても壊れない
- 素材ID(`enemy_minus_slime` など)は `src/assets/manifest.ts` にすでにある。**画像ファイルを置いて path を足すだけ**で差し替わる
- 生成は **ChatGPT(Pro)を Claude が先生の Chrome 上で操作**して行う(Q2 案A)。1回に1枚、先生の目の届く範囲で
- **先に基準画像を1枚決める**(T4-2: マイナススライム)。以後は基準画像を毎回添付して「同じ画風で」と頼む。これで画風がばらつかない
- 枚数は要件どおり絞る: 敵 40・人物 9・背景 21・タイトル 1 = **71 枚**。第1章分(P1: 敵 6・人物 6・背景 3・タイトル = 16 枚)を先に仕上げ、ゲームに入れて見てから次へ

## 2. 画風(決定: A. ドット絵風)

2026-09-24、同じ「マイナススライム」を 3 つの画風で作り、ゲームの戦闘画面に実寸で入れて見比べ、**A. ドット絵風** に決めた。
決め手: 100px に縮めても輪郭がいちばんはっきりしている/暗い戦闘画面でも目立つ/RPG の窓のドット書体と合う/とても軽い(1 枚 3KB)。
B は 100px で背景に溶けて見えにくく、C は星の模様が小さいとつぶれた。

**画風の一文(すべてのプロンプトの先頭に付ける)**:

> 16ビット時代の家庭用RPGの戦闘画面に出てくる敵キャラクターのような、ドット絵で。64×64ピクセル程度に見える、はっきりした四角いドット。輪郭は濃い色の1ドットの線。色数は12色程度に抑え、なめらかなグラデーションやぼかしは使わない。

(人物は「敵キャラクター」を「登場人物」に、背景は「戦闘画面の背景」に言いかえる)

**基準画像**: `assets-src/enemies/enemy_minus_slime.png`。以後の生成では毎回これを添付する。

## 3. 技術仕様

ChatGPT の画像は「ドット絵風」でもドットの大きさが不ぞろいなので、加工スクリプトで **決まったドット数に縮めて減色し、4 倍に拡大** する。これで 1 枚ごとの細かさ・色数がそろう。

| 種類 | ID の頭 | 生成サイズ | ドット数 → 書き出し | 色数 | 形式 | 背景 | 1 枚の目安 | ゲームでの表示 |
|---|---|---|---|---|---|---|---|---|
| 敵(雑魚) | `enemy_` | 正方形 | 64×64 → 256×256 | 16 | PNG | 透明 | 5KB | 100〜130px |
| 敵(ボス) | `enemy_` | 正方形 | 96×96 → 384×384 | 16 | PNG | 透明 | 10KB | 170px |
| 人物(立ち絵) | `char_` | 縦長 | 64×96 → 256×384 | 24 | PNG | 透明 | 8KB | 会話 130px・一覧 26〜56px |
| 背景・タイトル | `bg_` | 横長 | 240×160 → 960×640 | 32 | PNG | あり | 40KB | 会話の背景・拠点 |

- 加工: `python scripts/process_assets.py`(1 枚だけなら ID を付ける)。`assets-src/<種類>/<ID>.png` を読み、`public/assets/<種類>/<ID>.png` と `src/assets/paths.json` を書き出す。`paths.json` に載った ID は、`manifest.ts` を書き換えなくても画像で表示される
- ドット絵なので、ゲームでは `image-rendering: pixelated` のまま拡大する(ぼかさない)

- 置き場所: `public/assets/<種類>/<ID>.<拡張子>`(例: `public/assets/enemies/enemy_minus_slime.png`)。GitHub Pages から配信され、GAS の入口ページからは `assetUrl()` で読む
- 生成したままの元画像(1〜2MB)はリポジトリに入れない。`assets-src/`(`.gitignore` 済み)に置き、加工スクリプト(T4-4)で書き出す
- 全体で **約 1〜2MB**(ドット絵なので軽い)。画像は表示するときに 1 枚ずつ読まれ、ブラウザにキャッシュされるので、起動の速さには影響しない

## 4. 共通ルール(すべてのプロンプトに入れる)

1. **1 枚に 1 体(1 人・1 場面)**。全身が収まる。正面か、やや斜め
2. 敵・人物は **背景を透明**にする。影は描かない(ゲーム側で付ける)
3. **文字・数字・ロゴを描かない**。算数の記号は「−」「+」「×」「|」のような **単純な形の模様** としてだけ使う(AI は文字がくずれるため)
4. 中学生向け。**怖すぎない・流血なし**。魔物は「理のまちがいの姿」で、倒すと小動物や石に戻る → **どこか憎めない表情**
5. **既存の作品に似せない**。プロンプトに作品名・キャラ名・会社名を入れない(「ドラクエのスライム風」「ポケモン風」などは禁止)。とくにスライムは、しずく形に目と口の定番デザインにならないよう、体の形・質感を変える
6. 画風の基準画像を毎回添付し、「この画像と同じ画風・同じ線の太さ・同じ色数で」と書く
7. **数字・英字・記号は全角で入力する**(１６、ＲＰＧ、＋、（ ）)。Chrome の操作で半角文字が抜け落ちることがあったため。送る前に入力欄の文面を必ず目で確かめる

### プロンプトの型

```
(画風の一文 — T4-2 で決めたもの)
[何を]: {姿の説明}
[モチーフ]: {算数の要素。単純な形の模様として}
[表情・ポーズ]: {…}
[条件]: 1体だけ、全身、正面やや斜め、背景は透明、影なし、文字・数字・ロゴなし、中学生向けで怖すぎない
添付した基準画像と同じ画風・同じ線の太さ・同じ色数で。
```

## 6. 生成の手順(T4-2・T4-3)

1. 先生が Chrome で ChatGPT にログインしておく(Claude in Chrome が使える状態)
2. Claude が §4 の型でプロンプトを作り、**先生に見せてから** ChatGPT に送る
3. できた画像を先生と確認する(§8 のチェック)。直すときは「どこを・どう」だけを伝えて作り直す
4. 採用した画像のダウンロードは、**1 枚ずつ先生の許可を得て**行う(保存先: `assets-src/`)
5. 使ったプロンプトと採用日を §9 の記録に残す(作り直すときに同じ条件で頼めるように)
6. 加工スクリプト(T4-4)で書き出し → ゲームに入れて画面で確かめる

T4-2(基準画像)だけは、A・B・C の 3 画風でマイナススライムを作り、ゲームの戦闘画面に入れたスクリーンショットで先生に選んでもらう。

## 7. ゲームに入れるときの作業(T4-4・T4-5 で行う)

- 加工スクリプト: 透過の確認・余白の切り取り・リサイズ・(A なら)減色とドットの格子合わせ・WebP 変換・`manifest.ts` への path 追加
- 背景の使い回し: manifest に「別 ID と同じ画像」を書けるようにする
- 会話の背景: いまは絵文字だけなので、画像があれば全面に敷くようにする
- 加工スクリプトと `paths.json` の読み込み、背景の使い回し(`manifest.ts` の `alias`)と夕方の色(`tint`)、会話画面とタイトル画面の背景表示は作成済み(2026-09-24)
- 立ち絵(縦長)は会話画面・見た目選びで、枠の幅ではなく高さで表示する(`styles.css` の `.talk-actor img.sprite` / `.look-option img.sprite`)
- 小さい生き物は加工スクリプトの `FILL` で枠の中の大きさを決める(ピタ = 0.55、黒猫エックス = 0.5)
- 暗い色が 大半を しめる 絵(影の ボス・黒猫)は、減色で 小さな 明るい色(目・ベル)が 消える ことが ある → `OCTREE` に 入れて 色選びを FASTOCTREE に(2026-10-15)
