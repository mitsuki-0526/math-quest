# MathQuest 運用手順書(先生用)

- 作成日: 2026-09-20
- 対象: サーバー(スプレッドシート + GAS)の設定、公開、日々の操作、トラブル対応

## 全体像

```
生徒が開く URL = GAS Web アプリ(学校ドメイン限定)
┌──────────────────────────────────────────────────────┐
│ 入口ページ(GAS が返す)                                  │
│   ├─ ゲームのプログラム・画像 ◀── GitHub Pages(公開してよい静的ファイル) │
│   └─ セーブ・章の解放・設定 ──▶ GAS(google.script.run)──▶ スプレッドシート │
└──────────────────────────────────────────────────────┘
```

- 生徒が開くのは **GAS の URL**。学校の Google アカウントでログインしている人しか開けない
- ゲーム本体(プログラム・画像)は GitHub Pages から読み込む。更新は `main` に push すると自動で反映(GitHub Actions)。GAS 側は書き換えなくてよい
- 生徒のデータ(セーブ・成績)は Google の中(GAS とスプレッドシート)だけを通る。GitHub には送らない
- 生徒は **学校の Google アカウント** で本人確認される(合言葉なし)。クラス・出席番号は **先生が `roster` シートに貼った名簿** で決まり、生徒は選ばない(番号のまちがい・なりすまし登録が起きない)。名簿にない人は入れない
- 学校アカウントが取れない環境では、自動で「クラス・出席番号・合言葉」の方式になる(予備)
- GitHub Pages の URL を直接開くと「体験版」(その端末だけに保存・サーバーに送らない)になる

## 1. 初回セットアップ(30分)

### 1-1. スプレッドシートと GAS

1. Google ドライブで新しいスプレッドシートを作る(名前は例: `MathQuest_2026`)
2. メニュー「拡張機能」→「Apps Script」を開く
3. 開いたエディタの `コード.gs` の中身を全部消し、リポジトリの [gas/Code.gs](../gas/Code.gs) の内容を貼り付けて保存
4. エディタ上部の関数の選択で `setup` を選び「実行」。初回は権限の許可を求められるので許可する
   - `students` / `unlock` / `config` / `log` の4シートができる
5. `config` シートを開き、
   - `app_base_url` はゲーム本体の配信元(GitHub Pages)。通常は変えない
   - `teachers` に、ほかに先生として入る人の学校アカウントをカンマ区切りで書く(このスクリプトを作った先生は書かなくても先生)。先生は全章が解放された状態で入る
   - `roster` シートに名簿を貼る(次の 1-1b)
   - `teacher_pass` は予備の合言葉方式のときだけ使う(ランダムな値が入っている)
   - `classes` をクラス一覧にする(例: `1-1,1-2,1-3,1-4`)。ログイン画面の選択肢になる
6. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 説明: 任意 / 次のユーザーとして実行: **自分** / アクセスできるユーザー: **(学校名)内の全員**
   - 「デプロイ」→ 表示された **ウェブアプリの URL**(末尾 `/exec`)が、生徒に配る URL
   - 「全員」(匿名)にはしない。学校の外から開けるようになる

> **すでに本番の GAS を作ってある場合の更新手順**: `Code.gs` を新しい内容に貼り替えて保存 → `setup` をもう一度実行(足りないシート・設定の行が足される。既存のデータは消えない)→「デプロイを管理」→ 鉛筆 → バージョン「新バージョン」→「デプロイ」→ スプレッドシートを開き直す(「MathQuest」メニューが出る)

### 1-1b. 名簿(`roster` シート)

生徒 1 人を 1 行にする。

| email | class | number | memo |
|---|---|---|---|
| 生徒の学校アカウント | 1-2 | 7 | (自由。空でよい) |

- `email` は生徒が Chromebook にログインしているアカウント(大文字・小文字は区別しない)
- `class` は `config` の `classes` と同じ書き方(例: `1-2`)。`number` は出席番号
- `class` と `number` の列は `setup` が「書式なしテキスト」にしてある。ほかのシートから貼るときは **値のみ貼り付け**(Ctrl+Shift+V)にすると、`1-2` が日付に変わらない(変わっても読み取れるようにはしてある)
- メールアドレスの一覧は、Classroom の成績をスプレッドシートにコピーする機能や、学校の管理者から名簿を受け取って作れることが多い
- 同じアカウントが 2 行ある、または同じクラス・番号に 2 人いると、その生徒は入れず「名簿に まちがいが あるため 入れません」と出る(ほかの人のデータに触れないため)。`log` シートに `roster_conflict` が記録される
- 転入生・名簿の追加は、行を足すだけ。次に開いたときから入れる

> Code.gs を更新したときは、「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」→「デプロイ」。URL は変わらない。ゲーム本体の更新(GitHub への push)では、この操作は要らない。

### 1-2. GitHub Pages(ゲーム本体の配信元)

1. リポジトリ https://github.com/mitsuki-0526/math-quest の Settings → Pages → Source が **GitHub Actions** になっていることを確認(設定済み)
2. `main` に push すると Actions の「Deploy to GitHub Pages」が動き、数分で反映される
3. サーバーの URL や合言葉は GitHub に登録しない(Variables は不要)
4. GitHub アカウントには **2段階認証** を設定しておく(ここのプログラムが学校の GAS のページの中で動くため)

### 1-3. 動作確認

1. GAS の URL を開くと「先生 として 入ります(全章 解放)」と出る。「ぼうけんへ」で入れる
2. 生徒のアカウントでログインした Chromebook でも同じ URL を開けるか確認する
3. 学校の外の Google アカウント(個人の Gmail など)では開けないことを確認する
4. `students` シートに `teacher|t…` の行ができていれば、サーバー保存が動いている

## 2. 学期はじめ・年度はじめ

- `config` の `classes` を今年度のクラスに直す
- `unlock` シートを確認する。`*` の行が全クラスの既定値(最初は第1章だけ ✓)
- 前年度の生徒データを残す必要がなければ、`students` シートの 2 行目以降を削除する(ヘッダーは残す)

## 3. 日々の操作

### 3-1. 章を解放する(授業でその単元が終わったら)

`unlock` シートで、クラスの行の該当する章(g1c1〜g1c7)にチェックを入れる。

- クラスの行がなければ追加する(A列にクラス名、B列以降にチェックボックス)
- クラスの行がない場合は `*` の行が使われる
- 生徒側には **次にゲームを開いたとき**に反映される(遊んでいる最中なら一度タイトルに戻る)

| class | g1c1 | g1c2 | g1c3 | … |
|---|---|---|---|---|
| * | ☑ | ☐ | ☐ | |
| 1-1 | ☑ | ☑ | ☐ | |
| 1-2 | ☑ | ☐ | ☐ | |

### 3-2. 名簿をまちがえていた・番号が変わった

セーブは `students` シートの「クラス|番号」の行に入っている。名簿を直すだけだと、生徒は新しい番号の空の行で始まってしまう。

1. `roster` シートで、その生徒の `class` / `number` を正しい値に直す
2. `students` シートで、その生徒が遊んでいた行の `key`(例: `1-2|7`)・`class`・`number` を正しい値に書き換える(`key` は「クラス|番号」の形)
3. まだ遊んでいなければ 2 は不要

名簿にまちがいがあった場合に困るのは、2 人の生徒の番号が入れ替わっていたとき。そのままだと、お互いの記録で遊んでしまう。名簿を貼ったら、最初の授業の前に数人分を確かめておく(タイトルに「1-2 7番(名前 Lv)として 入ります」と出る)。

### 3-3. 合言葉を忘れた生徒(予備の合言葉方式のとき)

`students` シートでその生徒の行(`class` と `number` で探す)の **`pass_hash` と `salt` のセルを空にする**。生徒が次にログインするとき入力した合言葉が、新しい合言葉になる。セーブデータはそのまま残る。

合言葉を **8回続けてまちがえると、そのアカウントは10分間ログインできなくなる**(総当たり対策)。生徒には「10分ほど待ってから」と表示される。先生用アカウントも同じ(番号に関係なく、先生用全体で数える)。`log` シートに `locked` が記録される。

### 3-4. 授業の管理(「MathQuest」メニュー)

スプレッドシートの上部に「MathQuest」メニューがある(出ていなければスプレッドシートを開き直す。初めて使うときは権限の許可を求められる)。

| メニュー | 何が起きるか |
|---|---|
| **全員をタイトルに戻す** | 開いているゲームが、未保存の分を保存してから、**2分以内に**タイトル画面に戻る(「先生の 合図で タイトルに もどりました」と表示)。次に入るときは「1-2 7番(名前 Lv)として 入ります」を見てから押すことになる。授業の終わりに押す |
| **受付を停止する** | 生徒は入れず、保存もされない。開いているゲームは2分以内にタイトルに戻る。**先生は入れる** |
| **受付を再開する** | 生徒がまた入れる |

- 受付停止中に生徒の端末に残った分(停止の直前に遊んだ分)は、端末内に残り、次に入ったときに自動で送られる
- 曜日・時間で自動的に受付するには、`config` シートに書く(空欄なら毎日・一日中):
  - `open_days` … 受付する曜日。例: `月火水木金`
  - `open_hours` … 受付する時間。例: `08:30-12:30,13:20-15:40`(時刻は `08:30` のように 2 けたで。書き方がまちがっている範囲は無視される)
  - メニューの「受付を停止する」は、曜日・時間の設定より優先される(停止中は時間内でも入れない)
- 家庭学習でも使うなら、`open_hours` は空欄のままにする(または家庭学習の時間まで含める)

> **ゲームの機能だけでは防げないこと**: ゲームは「Chromebook にログインしているアカウント=本人」として動く。ログインしたまま置いてある Chromebook は、ほかの生徒がその生徒として(ゲームに限らず Classroom やドライブも)使えてしまう。これを確実に防ぐには、情報担当の先生に Google 管理コンソールで **「一定時間操作がなければ画面をロック(またはログアウト)」** を設定してもらう。生徒には、席を離れるときの画面ロック(**検索キー + L**)を指導する。

### 3-5. 進捗を見る(集計は今後の機能)

`students` シートの `save_json` 列に生徒ごとのセーブが JSON で入っている。`player_name` `updated_at` `last_seen` で最終プレイ日時が分かる。単元別正答率の一覧シート(`summary`)は今後追加予定(要件 F71)。

### 3-6. ゲームの調整値を変える

`config` シートに `key` と `value` を追加すると、ゲーム側の数値を上書きできる(生徒が次に開いたときから)。キーはドット区切り。

| key | 意味 | 既定値 |
|---|---|---|
| `battle.hintsPerNode` | 1ノードで使えるヒント回数 | 3 |
| `battle.baseDamage` | 基礎ダメージ | 8 |
| `battle.timeMin` / `battle.timeMax` | 制限時間の下限/上限(秒) | 15 / 120 |
| `defeat.goldLossRatio` | 敗北時に失うゴールドの割合 | 0.1 |
| `level.base` | レベルアップに必要な経験値の基準 | 50 |
| `adaptive.upAt` / `adaptive.downAt` | 直近6問中の正答数で ★ を上げる/下げる境目 | 5 / 2 |

全キーは [src/data/config.ts](../src/data/config.ts) を参照。

## 4. 生徒への説明(最初の授業)

1. URL(Classroom の投稿や QR コード)を、学校のアカウントでログインした Chromebook で開く
2. 「1-2 7番 として 入ります」と出る。**自分のクラス・番号か確かめさせる**(ちがったら押さずに先生へ)→「ぼうけんへ」
3. 初回は見た目と主人公の名前を決める → 物語が始まる
4. 2回目からは「1-2 7番(ミナ Lv3)として 入ります」→「ぼうけんへ」だけ。別の Chromebook でも同じアカウントなら続きから遊べる
5. **席を離れるときは画面をロックする(検索キー + L)**。ログインしたままの Chromebook は、ほかの人がその人として遊べてしまう(Classroom やドライブと同じ)
6. 画面右上に「同期済み」と出ていれば保存されている。「オフライン」のときは端末に保存され、つながったときに送られる
7. 別の人に代わるときは Chromebook からログアウトする(ゲームの中にはログアウトはない)

## 5. 開発者向け(ローカルで動かす)

```bash
npm install
node scripts/mock-server.mjs     # GAS の代わり(メモリ上。合言葉方式。先生の合言葉は sensei)
MOCK_EMAIL=s1@school.example node scripts/mock-server.mjs   # 学校アカウント方式を再現(MOCK_TEACHERS で先生のアカウント)
npm run dev                      # .env.local に VITE_GAS_URL=http://127.0.0.1:8787 / VITE_API_TOKEN=dev-token
```

- 開発中は fetch でモックサーバーと通信する。本番(GAS の入口ページの中)では自動で google.script.run に切り替わる(`src/engine/api.ts`)
- 本番の GAS は学校ドメイン限定なので、外部からの負荷試験はできない。最初の授業の前に、1クラス分(30〜35台)で同時に開いて確かめる

## 6. トラブル対応

| 症状 | 原因の候補 | 対応 |
|---|---|---|
| 「ゲームを 読み込めませんでした」 | GitHub Pages が開けない(フィルタ・障害)/ `config` の `app_base_url` が違う | Chromebook で https://mitsuki-0526.github.io/math-quest/ が開けるか確認。`app_base_url` を空にすると既定値に戻る |
| 「アクセス権がありません」と出る | 学校以外のアカウントで開いている / デプロイのアクセス範囲 | 学校のアカウントでログインし直す。デプロイ設定が「(学校名)内の全員」か確認 |
| ログイン画面で「サーバーに つながりません」 | 通信が不安定 / GAS の一時的な失敗 | 少し待って再読み込み。前回その端末で入った本人なら、端末内のセーブで続けられる |
| ゲームの URL(github.io)が学校で開けない | ネットワークフィルタ | 情報担当に `*.github.io` の許可を依頼。難しければ GAS の HtmlService 配信に切り替える(要件 §7.2 の代替案) |
| 生徒の進みが消えた | 別のアカウントで開いた / (合言葉方式)別の合言葉で新規登録した | Chromebook のログインアカウントを確認。`students` シートで同じ番号の行が2つないか確認し、古い行の `save_json` を正しい行にコピー |
| 「この アカウントは 名簿に ありません」 | `roster` にその生徒がいない / アカウントの打ちまちがい | `roster` に行を足す・直す。生徒には「もう一度 つなぐ」を押してもらう |
| 「いまは 遊べない 時間です」 | 受付停止中 / `open_days`・`open_hours` の時間外 | メニューの「受付を再開する」。時間の設定を確認(`config` シート) |
| 「名簿に まちがいが あるため 入れません」 | 同じアカウントが 2 行、または同じクラス・番号に 2 人 | `roster` の重複を直す(`log` シートの `roster_conflict` にクラス・番号が出る) |
| タイトルに別の人の名前が出る | ログインしたままの他人の Chromebook / 名簿の入れ替わり | 押さずに端末の持ち主を確認。名簿の入れ替わりなら 3-2 |
| 章を解放したのに🔒のまま | 反映は次回起動時 | 一度タイトルに戻ってログインし直す |
| 同期が「未同期(再試行中)」のまま | GAS の一時的な失敗 / 1日の実行上限 | 数分待つ。`log` シートの error を確認 |
| セーブが大きすぎる(save_too_large) | 想定外。連絡 | `students` の該当行の `save_json` を確認 |
| 「合言葉の まちがいが 続いたので…」 | 合言葉を8回続けてまちがえた | 10分待つ。忘れているなら 3-3 の手順でリセット |
| 「サーバーに つながりません」の画面 | オフライン | 前回この端末で入った本人なら「この端末の 記録で つづける」で遊べる(つながったら自動で送る)。「もう一度 つなぐ」で再接続 |

## 7. データとプライバシー

- `students` シートに保存しているのは クラス・出席番号・主人公名(ニックネーム)・ゲームの進行と単元別の正答数。実名とメールアドレスは入らない
- 学校アカウントは `roster`(名簿)シートにだけある。先生が貼ったもので、ゲームは読むだけ。生徒には見えない(スクリプトは先生の権限で動き、シートは先生だけが開ける)
- 生徒ができるのは「自分のアカウントに名簿で結び付いた行」の読み書きだけ。画面を改造してほかのクラス・番号を送っても、サーバーはそれを見ずにアカウントと名簿で行を決める
- 予備の合言葉方式では、合言葉を SHA-256 + ソルトでハッシュ化して保存(先生も見られない)。生徒の端末には入力の手間を省くため合言葉が保存される
- 1台の Chromebook を複数の生徒が使っても、端末内のセーブは「クラス・番号」ごとに分けて保存される
- 生徒が入力した値(クラス・番号・主人公名)はシートに文字列として書く(`=` などで始まっても数式として動かない)
- スプレッドシートの共有は先生のみにする。GAS の実行ユーザーは先生本人
- 年度末にデータを消す場合は `students` シートの行を削除する
