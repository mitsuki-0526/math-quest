# MathQuest 運用手順書(先生用)

- 作成日: 2026-09-20
- 対象: サーバー(スプレッドシート + GAS)の設定、公開、日々の操作、トラブル対応

## 全体像

```
生徒の Chromebook ──(ブラウザ)──▶ GitHub Pages(ゲーム本体・静的ファイル)
        │
        └──(セーブ・章の解放・設定)──▶ GAS Web アプリ ──▶ 先生のスプレッドシート
```

- ゲーム本体は GitHub Pages に置く(無料)。更新は `main` に push すると自動で反映(GitHub Actions)
- セーブデータ・章の解放・調整値は、先生の Google アカウントのスプレッドシートに入る
- 生徒は「クラス・出席番号・合言葉」でログイン。氏名は保存しない

## 1. 初回セットアップ(30分)

### 1-1. スプレッドシートと GAS

1. Google ドライブで新しいスプレッドシートを作る(名前は例: `MathQuest_2026`)
2. メニュー「拡張機能」→「Apps Script」を開く
3. 開いたエディタの `コード.gs` の中身を全部消し、リポジトリの [gas/Code.gs](../gas/Code.gs) の内容を貼り付けて保存
4. エディタ上部の関数の選択で `setup` を選び「実行」。初回は権限の許可を求められるので許可する
   - `students` / `unlock` / `config` / `log` の4シートができる
5. `config` シートを開き、
   - `api_token` の値をメモする(自動生成されている)
   - `teacher_pass` を確認する(先生用アカウントの合言葉。ランダムな値が自動で入っている。覚えやすい値に変えてよいが、生徒に推測されないものにする。プログラムは公開リポジトリにあるので、既定値は置いていない)
   - `classes` をクラス一覧にする(例: `1-1,1-2,1-3,1-4`)。ログイン画面の選択肢になる
6. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 説明: 任意 / 次のユーザーとして実行: **自分** / アクセスできるユーザー: **全員**
   - 「デプロイ」→ 表示された **ウェブアプリの URL**(末尾 `/exec`)をメモする

> Code.gs を更新したときは、「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」→「デプロイ」。URL は変わらない。

### 1-2. GitHub Pages

1. GitHub にリポジトリを作り、このプロジェクトを push する
2. Settings → Pages → Build and deployment の Source を **GitHub Actions** にする
3. Settings → Secrets and variables → Actions → **Variables** タブで追加:
   - `VITE_GAS_URL` = 1-1 でメモした URL
   - `VITE_API_TOKEN` = `api_token` の値
4. Actions タブで「Deploy to GitHub Pages」が成功すれば `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される

### 1-3. 動作確認

1. 公開 URL を開き、「先生用」→ `teacher_pass` の合言葉で入る。全章が解放された状態で遊べる
2. 学校の Chromebook でも同じ URL を開けるか確認する(フィルタで開けない場合は §6)
3. `students` シートに `teacher|0` の行ができていれば、サーバー保存が動いている

## 2. 学期はじめ・年度はじめ

- `config` の `classes` を今年度のクラスに直す
- `unlock` シートを確認する。`*` の行が全クラスの既定値(最初は第1章だけ ✓)
- 前年度の生徒データを残す必要がなければ、`students` シートの 2 行目以降を削除する(ヘッダーは残す)

## 3. 日々の操作

### 3-1. 章を解放する(授業でその単元が終わったら)

`unlock` シートで、クラスの行の該当する章(g1c1〜g1c7)にチェックを入れる。

- クラスの行がなければ追加する(A列にクラス名、B列以降にチェックボックス)
- クラスの行がない場合は `*` の行が使われる
- 生徒側には **次にゲームを開いたとき**に反映される(遊んでいる最中なら一度タイトルに戻る)

| class | g1c1 | g1c2 | g1c3 | … |
|---|---|---|---|---|
| * | ☑ | ☐ | ☐ | |
| 1-1 | ☑ | ☑ | ☐ | |
| 1-2 | ☑ | ☐ | ☐ | |

### 3-2. 合言葉を忘れた生徒

`students` シートでその生徒の行(`class` と `number` で探す)の **`pass_hash` と `salt` のセルを空にする**。生徒が次にログインするとき入力した合言葉が、新しい合言葉になる。セーブデータはそのまま残る。

合言葉を **8回続けてまちがえると、そのアカウントは10分間ログインできなくなる**(総当たり対策)。生徒には「10分ほど待ってから」と表示される。先生用アカウントも同じ(番号に関係なく、先生用全体で数える)。`log` シートに `locked` が記録される。

### 3-3. 進捗を見る(集計は今後の機能)

`students` シートの `save_json` 列に生徒ごとのセーブが JSON で入っている。`player_name` `updated_at` `last_seen` で最終プレイ日時が分かる。単元別正答率の一覧シート(`summary`)は今後追加予定(要件 F71)。

### 3-4. ゲームの調整値を変える

`config` シートに `key` と `value` を追加すると、ゲーム側の数値を上書きできる(生徒が次に開いたときから)。キーはドット区切り。

| key | 意味 | 既定値 |
|---|---|---|
| `battle.hintsPerNode` | 1ノードで使えるヒント回数 | 3 |
| `battle.baseDamage` | 基礎ダメージ | 8 |
| `battle.timeMin` / `battle.timeMax` | 制限時間の下限/上限(秒) | 15 / 120 |
| `defeat.goldLossRatio` | 敗北時に失うゴールドの割合 | 0.1 |
| `level.base` | レベルアップに必要な経験値の基準 | 50 |
| `adaptive.upAt` / `adaptive.downAt` | 直近6問中の正答数で ★ を上げる/下げる境目 | 5 / 2 |

全キーは [src/data/config.ts](../src/data/config.ts) を参照。

## 4. 生徒への説明(最初の授業)

1. URL(またはQRコード)を開く
2. クラスと出席番号を選び、**合言葉を自分で決めて**入力(ひらがな・数字OK。忘れにくいもの)
3. 「ぼうけんへ」→ 主人公の名前を決める → 物語が始まる
4. 別の Chromebook で開いても、同じクラス・番号・合言葉で続きから遊べる
5. 画面右上に「同期済み」と出ていれば保存されている。「オフライン」のときは端末に保存され、つながったときに送られる

## 5. 開発者向け(ローカルで動かす)

```bash
npm install
node scripts/mock-server.mjs     # GAS の代わり(メモリ上。先生の合言葉は sensei)
npm run dev                      # .env.local に VITE_GAS_URL=http://127.0.0.1:8787 / VITE_API_TOKEN=dev-token
```

負荷試験(本番 GAS に対して。終わったら `students` シートの `loadtest` クラスの行を削除):

```bash
node scripts/loadtest.mjs https://script.google.com/macros/s/xxxx/exec <api_token> 35
```

## 6. トラブル対応

| 症状 | 原因の候補 | 対応 |
|---|---|---|
| ログイン画面で「サーバーに つながりません」 | GAS の URL が違う / デプロイの「アクセスできるユーザー」が「全員」でない / 学校のフィルタ | URL を確認。デプロイ設定を確認。Chromebook で `https://script.google.com` が開けるか確認 |
| 「サーバーの設定が 合っていません」 | `api_token` の不一致 | `config` シートの値と GitHub の Variables を見比べ、直したら Actions を再実行 |
| ゲームの URL(github.io)が学校で開けない | ネットワークフィルタ | 情報担当に `*.github.io` の許可を依頼。難しければ GAS の HtmlService 配信に切り替える(要件 §7.2 の代替案) |
| 生徒の進みが消えた | 別の合言葉で新規登録した(別の行ができる) | `students` シートで同じ番号の行が2つないか確認。古い行の `save_json` を正しい行にコピー |
| 章を解放したのに🔒のまま | 反映は次回起動時 | 一度タイトルに戻ってログインし直す |
| 同期が「未同期(再試行中)」のまま | GAS の一時的な失敗 / 1日の実行上限 | 数分待つ。`log` シートの error を確認 |
| セーブが大きすぎる(save_too_large) | 想定外。連絡 | `students` の該当行の `save_json` を確認 |
| 「合言葉の まちがいが 続いたので…」 | 合言葉を8回続けてまちがえた | 10分待つ。忘れているなら 3-2 の手順でリセット |
| 回線が切れたままタイトルに戻った | オフライン | 前回この端末で入った本人なら、同じクラス・番号・合言葉で端末内のセーブから続けられる(つながったら自動で送る) |

## 7. データとプライバシー

- 保存しているのは クラス・出席番号・合言葉のハッシュ・主人公名(ニックネーム)・ゲームの進行と単元別の正答数。実名は保存しない
- 合言葉は SHA-256 + ソルトでハッシュ化して保存(先生も見られない)。生徒の端末には入力の手間を省くため合言葉が保存される
- 1台の Chromebook を複数の生徒が使っても、端末内のセーブは「クラス・番号」ごとに分けて保存される。交代するときは 設定 →「ログアウト(別の人に代わる)」
- 生徒が入力した値(クラス・番号・主人公名)はシートに文字列として書く(`=` などで始まっても数式として動かない)
- スプレッドシートの共有は先生のみにする。GAS の実行ユーザーは先生本人
- 年度末にデータを消す場合は `students` シートの行を削除する
