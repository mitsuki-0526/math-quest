## 問題の品質の 仕組み(2026-09-29)

「良い問題を 100% 作る」ことだけを ねらわず、**作る → 検査する → 合格した 問題だけ ゲームに 渡す → 不合格は 理由を 記録する** 形に した(EDUMATH の 考え方。ChatGPT の 提案を 先生と 検討して 採用)。問題は すべて プログラムで 作り、**ゲームの 中では AI(LLM)を 使わない**(生徒の データを 外に 出さない・速さ・費用)。

```
ProblemSpec(仕様: src/data/grade1/specs.ts)
↓
Generator(出題タイプの プログラム: src/data/grade1/problems/*.ts)
↓
MathValidator(数学の 検査: 答えが 成り立つ・解説の 答えと 一致・選択肢・式・文字化け)
↓
Spec の 検査(数の 範囲・個数・答えの 範囲・素因数分解の 数)
↓
Judge(教育的な ルール: 絶対値の 記号・係数の 分母の 文字・2 文字の 同類項・先生の ×)
↓
DuplicateChecker(同じ 出題タイプの 直近 20 問と 同じ・同じ形の 3 連続。直近 20 問は セーブに 残し、地点を 移っても 避ける。2026-10-14 先生の指摘「同じ 問題を 何回も 見た」で 6 問 → 20 問)
↓
合格 → ゲームへ / 不合格 → 理由を ログに 残して 作り直す(最大 8 回)
```

- 入口は `generateProblem()`(`src/math/template.ts`)。戦闘・見本帳・修練の泉は 何も 変えずに この流れを 通る
- 部品は `src/math/quality/`: `spec.ts` `mathValidator.ts` `judge.ts` `duplicateChecker.ts` `rejectReason.ts` `generationLog.ts` `judging.ts`。Judge の ルールは 学年・単元の 決まり(`rules/curriculum.ts`。単元で 当てる・ほかの ゲームへ 持っていける)と ゲームごとの ルール(`registerJudgeRules`)に 分けてある。ほかの ゲームで 使う 手順は [quality-kit.md](quality-kit.md)。先生の 判定は `review:import` で `quality/judgments.jsonl` に 記録として たまる
- **どれも 合格しない とき**: 重複だけが 理由の 候補が あれば それを(問題の 種類が 少ない ★1 など)、なければ ★ を 1 つ 下げる、★1 でも だめなら 最後の 候補を「検査なし」として 出す(問題が 出ないよりは よい)。ログに `fallback` として 残る
- **不合格の 理由**(`rejectReason.ts`): GENERATOR_ERROR / INVALID_ANSWER / ANSWER_MISMATCH / INVALID_CHOICE / INVALID_EXPRESSION / BROKEN_TEXT / MISTAKE_EQUALS_ANSWER / SPEC_VIOLATION / OUT_OF_SCOPE / TEACHER_REJECTED(ここまで 品質) / DUPLICATE / SAME_FORM(重複による 作り直し)
- **ログ**: 端末の メモリに 直近 2000 件(個人情報なし)。開発中は ブラウザの コンソールで `__mqGenerationLog()`。将来 良問/悪問の 分類に 使えるよう、候補ごとに 1 行・理由の コードで 残す
- **テストとの 役割分担**: テスト(`tests/templates.test.ts`)は 別解法の 式(verify)で 答えを 照合する。ゲームの 中の MathValidator は 式を 実行しないで 確かめられる ことだけを 見る

## 解説と「よくある まちがい」(全単元共通、2026-09-29)

問題には **教科書の 手順どおりの 解説** と **よくある まちがい**(`Problem.mistakes`: 誤答の値 + ピタの一言)を 付ける。生徒が その値を 入れたら、解説の いちばん上に その子に合った 一言が 出る(「きみの答え」と「正解」も 並べて 見せる)。先生の要望「まちがい方に合わせた解説」「解説の手順を ていねいに」。

- 誤答の値は テンプレートの中で 計算する(例: (−7) − (−2) の −(−2) を −2 のまま → −9)。正解と 同じ値になったものは `generateProblem` が 取り除く
- 第1章で 入れた まちがい: 加減(−(−b) を −b / +(−b) を +b / 符号だけ 逆)、乗除(符号 / ×÷ を 左から にしない / ÷ を 逆数に しない)、累乗((−3)² と −3² / 3² を 6)、四則(左から 順に 計算)、絶対値(負の数を 答える / 絶対値で 大小を 比べる / 0 を 数え忘れる / 端を ふくめる)、数直線(向き / 0 を またぐ 距離)、基準との差(符号 / 差の合計だけ / 目標を たし忘れ)
- 加減の解説: ① ひき算を たし算に ② かっこを はずす ③ 正の項・負の項を まとめる ④ 計算(大きいほうの 絶対値から 小さいほうを ひき、その符号)
- 新しいテンプレートを作るときも 付ける。`tests/mistakes.test.ts` が 誤答の値を 別の計算で 確かめる

## 分数の 入れ方の 補助(全単元共通、2026-10-04)

先生の指摘「/ で 分数を 入れることに 慣れていない 生徒が ほとんど」。答えが 分数の 問題(`needsFractionInput`: 数の 答えが 分数、または 式の 係数に 分数。小数で 見せる 答えは のぞく)で:

- **はじめての 1 回だけ** ピタの 練習が 出る(`FractionPractice`)。3/4 を 実際に 打たせ、「こう読みます」で 分数の 形に なるのを 見せる。「/」を 使わない・まちがえたら 言い直し。練習の 間は 時間を 止める。終わると セーブの `tut:fraction` が 立つ
- **毎回**、入力欄の 下に 見本(「分数は 分子 → / → 分母 の 順に 押します: 3/4 → ¾」。式なら 2/3x)を 出し、「/」キーを 金の 枠で 目立たせる

## ★ の決め方(全単元共通)

| ★ | 目安 | 正答率のめやす |
|---|---|---|
| ★1 | 教科書の例題・確かめの問題。1 回の計算、1けたの数 | 90% 以上 |
| ★2 | 教科書の練習問題。チャレンジテストの基本計算 | 80〜90% |
| ★3 | 章末問題・問題集の標準。チャレンジテストの四則混合 | 50〜75% |
| ボス | ★3 の上限。数を大きくする/段階を増やす。ボス戦でだけ出す | — |

★ は生徒ごとに自動で上下する(直近 6 問で 5 問正解なら上がる、2 問以下なら下がる)。

**★3(難問)は 道中では 数問だけ(`battle.hardPerBattle` = 2、2026-09-27)**: 道中の戦闘では ★3 は **その地点の最後の戦闘でだけ**、合わせて 2 問まで出す(それ以外は ★2 にする)。とくに難しいタイプ(基準との差・平均)は 1 問まで(テンプレートの `hardPerBattle`)。ボス戦と修練の泉には かからない。先生の印「難問を いくつも 解くのは しんどい。数問 解けば クリアできる ところで」

**道中は教科書、修練の泉はチャレンジテスト(`ProblemBasis`、2026-09-28)**: 先生の方針「道中は チャレンジテストより 教科書に合わせる。修練の泉は チャレンジテスト基準で」。テンプレートの `generate(rng, ★, basis)` に `'textbook'`(道中・ボス。省略時)か `'challenge'`(修練の泉)が渡る。見本帳の「修練の泉」も challenge で並ぶ。違いがあるのは今のところ 基準との差・平均 の表の数だけ。ほかのテンプレートは 教科書とチャレンジテストで 同じ範囲にしている

**出題タイプごとの下限(`minStars`、2026-10-13)**: 地点ごとに、出題タイプの ★ の下限を決められる(上限は こえない)。★ が 自動で 上がらない 子にも 1 段 上の 問題に 触れさせるため。第2章の 草原の道(★2 まで)では 代入を ★2 から 出し、1 戦目に 文字の妖精エックスを 置いた(先生の要望「道中でも レベル 2 の 代入に 触れさせたい」)

**地点ごとの上限(`maxStar`、2026-09-26)**: 各章の 1 つめの戦闘は ★1 まで、2 つめは ★2 まで。生徒の ★ が高くても、その地点では上限までの問題しか出ない。章の最初は「習いたてでも解ける」ようにするため(先生の試遊での指摘)。修練の泉と ボスには上限がない。
