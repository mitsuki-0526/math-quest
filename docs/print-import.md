# 授業のプリントを難しさの基準にする(ローカル LLM)

- 作成日: 2026-10-01(先生の提案「授業で使っている市販のプリントを取り込みたい。ローカル LLM も」)
- 関連: [difficulty.md](difficulty.md)(★ ごとの仕様)、[quality-kit.md](quality-kit.md)

## 線引き(いちばん大事)

- このリポジトリは **公開**(GitHub Pages)。**プリントの問題文・式・画像は リポジトリにも ゲームにも 入れない**
- 取り出すのは教科書と同じく **「仕様」だけ**: 問題の形(数を # にした形)・項の数・数の範囲・2 けたの割合・かっこ/累乗/小数/分数の割合
- ゲームの問題はこれまでどおりプログラムが作る(プリントと同じ「形と難しさ」の、別の問題)
- 画像・読み取りの生データ・要確認の一覧は `refs/prints/`(Git に上げない)。外のサービスには送らない
- プリントの使用条件(購入した学校の授業での利用 など)は先生が確かめる

## 読み取りの仕組み

```
プリントの PDF か 画像(150dpi)── 幅 900px に 縮める
  ↓ この パソコンの ローカル LLM(Ollama + qwen3-vl:8b-instruct、GPU = Intel Arc)
  ↓ 式を 書き写させる だけ(計算させない)。解答の ページは 見分けて 飛ばす
  ↓ 問題の ページは 2 回 読ませる(2 回目は 符号・かっこ・指数に 注意)
  ↓ 2 回が 食い違う・式の 欄に 文章が ある 問題は「要確認」に(集計には 入れない)
プログラムが 特徴を 計算(scripts/print-features.mjs: 項の数・数の範囲・形、数 1 つの 問題は 素因数の 個数・最大の 素因数・指数)
  ↓
特徴の 集計(<フォルダ>-features.md: 式は ふくまない)→ Claude が 仕様(specs.ts・difficulty.md)と 問題の作り方を 直す
  ↓
先生が「1 問ずつ ○× 判定」で 確かめる
```

モデルの選び方(2026-10-01): このパソコン(Core Ultra 7 258V・メモリ 32GB・Intel Arc 140V)では、日本語と数式の読み取りに強い **qwen3-vl:8b-instruct**(約 6GB。考えない 版)。考える 版(qwen3-vl:8b)は 答えの 前に 英語で 長く 考え(`think: false` でも 止まらない)、1 回 5〜17 分 かかって 途中で 落ちた。入っていた gemma3:4b・gemma4:e4b は小さく、数式の マイナスを 落としやすい(外部の比較)。もっと正確さが 要るときは qwen3-vl:30b(約 20GB。このパソコンでは ぎりぎり)。Ollama は 標準では GPU を 使わないので、道具は `OLLAMA_VULKAN=1` で 起動する。あわせて `OLLAMA_FLASH_ATTENTION=0`(Vulkan で Flash Attention が 入っていると、画像を 渡した ところで 落ちる。2026-10-01 に 確かめた)。GPU なしだと 1 回の 読み取りに 5 分 以上 かかり、実用に ならない。

### 精度(2026-10-01)

| 試した もの | 結果 |
|---|---|
| 作った 試しの プリント(加減 12 問: 小数・分数・かっこ・3〜4 項) | 12 問 すべて 正しい(符号・かっこ・小数・分数も) |
| 授業の プリント 素因数分解(定着・標準・発展 10 ページ。Claude が 画像から 作った 正解と 比べた) | 解答の ページの 見分け 10/10。素因数分解する 数 17/17。「累乗で 表す」3/4(同じ 数字が 4 つ 並ぶ 所で 1 つ 落とす。2 回とも 同じに 読むので 要確認に 出ない) |
| 速さ | 問題の ページ 1〜2 分半(2 回)、解答の ページ 約 1 分。10 ページ 約 15 分 |

わかった こと:
- **数・式の 書き写しは 正確**。弱いのは「同じ 数字が 4 つ 以上 並ぶ」所(数え 違える)
- **文章題・表・穴うめ**(素数の 表、約数を 求める、発展の 問題)は 式に ならず 要確認に 回る。集計には 入らない(形の 種類だけ 先生が 見る)
- **説明の 枠(用語の 説明・例)を 問題と して 拾う** ことが ある。式の 欄に 文章が 入った ものは 集計から 外す(`isMathExpr`。集計は 外に 出す ファイルなので、プリントの 文章を 入れない)
- **元の 大きさ(幅 1240px)だと、ない 問題を でっち上げる**(30 問 作った)。幅 900px で 読ませる

## 使い方

1. プリントの **PDF** を 単元ごとの フォルダに 置く: `refs/prints/加減/加減.pdf`(ページごとの 画像に 自動で する。Python の pypdfium2 を 使う)。紙なら **150dpi** で スキャンして `p01.png` … と 置く。解答・解説の ページが まざって いても よい(PDF の 見出しに「解答」が あれば 読まずに 飛ばす。見出しが なければ LLM が 見分ける。第1章 84 ページで 見分けは すべて 正しかった)
2. `npm run print:extract -- refs/prints/加減`(問題の ページ 1〜2 分半、解答の ページ 約 1 分)。前に 読んだ ページは 読み直さない(`--fresh` で 読み直す)
3. `refs/prints/加減-check.md`(要確認)を プリントと 見比べる。読み違いが 多ければ 解像度や 撮り方を 変える
4. `refs/prints/加減-features.md`(特徴の 集計。式は ふくまない)を Claude との チャットに 貼る
5. Claude が 仕様と 問題の作り方を 直し、先生が 判定画面で 確かめる
